# 下屏输入交接与左键遗留修复

用户报告鼠标左键偶发持续按下、下屏触摸位置偏移或乱点。维护连接恢复后先保存输入设备状态、窗口几何和日志，没有先重启图形会话。

## 现场与可复现缺陷

当前读取时所有实体/虚拟输入设备的按键状态均已松开，触摸板已隐藏；日志中曾显示触摸板后切回键盘。X11 的 XQueryPointer 也读到 state_mask=0。没有把静态检查通过写成本次故障已经复现。

下屏 Goodix 仍绑定 DSI-2，校准矩阵为单位矩阵；输出右旋、逻辑位置 283,720、尺寸约 820×615、缩放 1.25。上屏绑定 DSI-1。按这组布局验证原始触点到 GTK 控件的换算，没有发现需要额外添加全局偏移或缩放的证据。仅凭当时的配置快照，不能判定用户报告的偏移是否已经消失。

源码回放确认以下独立问题：

1. 重新显示触摸板后，80 ms 布局初始化前收到左键按下，随后重新配置路由清掉触点归属，松手事件被丢弃，虚拟左键仍按下。
2. 原始输入短时不可用时，GTK 接管了拖动；原始输入恢复后，GTK 的结束或取消事件被提前忽略，拖动没有释放。
3. Type-B 多点触摸的新 tracking ID 不代表槽位坐标失效。清掉不变的 X/Y 会漏掉只报告变化轴的触点。显示切换或其他进程独占触屏之后，仅修新 ID 的处理仍不够，还需要重新同步内核缓存。

协议依据：[Linux 多点触摸协议](https://kernel.org/doc/html/latest/input/multi-touch-protocol.html)、[输入事件及 SYN_DROPPED](https://kernel.org/doc/html/latest/input/event-codes.html)。

## 修复范围

仅涉及键盘、触摸板及共享的下屏原始输入解码。布局未就偏移症状作猜测性校准。

- 布局完成前不接收触点；隐藏时取消旧初始化回调；重新配置前先释放按钮和手势归属。
- GTK 与原始输入交接时取消旧拖动；已过期的异步事件不得影响新一轮输入。
- 保留连续 Type-B 流中的槽位坐标；交接、重新打开和丢帧恢复时，从内核缓存建立新的输入起点，已有手指不作为新点击。
- 触摸板手势、按钮归属及原始触点测试加入默认测试入口。

实体下屏偏移和正常触摸操作的最终验收不以离线测试替代。

## 另行记录的手柄测试边界

检查还发现精确 InputPlumber 源码中的独立风险：joymouse 按住 R1 时进入手柄测试，鼠标 target 的 clear_state 只清移动量；接管后的松手可能没有送回该虚拟鼠标。纯边界模型能够复现恢复 idle 后仍留 BTN_LEFT，但本次现场没有对应操作证据。本轮没有修改 InputPlumber 或重建它的 target，也不把该模型当作本次实机根因。后续开源准备分支已单独提供 [源码补丁和验证说明](../../components/inputplumber/MOUSE-CLEAR.md)，按 PDS-059 跟踪；它没有随本次触摸修复部署。
