# 架构

本项目是 Pocket DS 定制 Linux 环境上的设备适配与桌面覆盖层。
内核、固件、KWin、PipeWire、InputPlumber 及外部应用仍由各自的软件包提供；仓库保存我们的
组件、配置、针对上游的补丁、来源记录、测试及安装工具。

## 组件与职责

| 组件 | 运行位置 | 职责与接口 |
|---|---|---|
| Panel | Plasma 的 QML 小部件 | 通过 `pocketds-panelctl` 读取状态和发起操作，独立查询合盖模式 |
| `pocketds-panelctl` | 短命 C++ 用户进程 | 输出有字段校验的 JSON；调用用户服务或受限系统助手 |
| 键盘与触摸板 | 默认隐藏的 GTK/XWayland 用户服务 | 用 uinput 输出按键/相对鼠标事件，通过用户服务切换显示 |
| GPU/显示遥测 | 用户服务 | 采样用户可见 DRM 客户端和 KWin 输出，原子写入运行目录缓存 |
| Codex 额度 | 用户定时任务 | 使用用户已安装、登录的 Codex 获取额度，Panel 只读取本地结果 |
| 输入模式与手柄测试 | 系统服务及受限助手 | 协调 InputPlumber 模式、临时按键测试和游戏会话恢复 |
| 亮度与合盖 | 用户服务、系统助手、KDE 电源管理 | 管理双背光目标、关屏/恢复与睡眠前的显示准备 |
| 音频 | ALSA UCM、PipeWire/WirePlumber 用户服务 | 声卡就绪、扬声器增强及录音源选择 |

普通音量、窗口操作和界面切换在用户会话中执行。需要权限的背光、风扇和系统操作走固定入口，
由助手校验允许的动作与参数；安装后的 sudoers/polkit 规则是这一边界的一部分。调整调用时，
必须同时检查助手、策略、调用方和部署顺序。

## Panel 状态与动作

主界面按周期读取状态；GPU、风扇、额度等数据有各自的有效性与新鲜度要求。缓存损坏或某个
数据源缺失时，只让对应区域不可用，不能把未知值替换为正常的 0。GUI 发出命令与硬件操作
完成是不同阶段；需要回读确认的动作保留 pending 状态，过时查询不能确认新命令。

GPU 利用率表示当前用户可观察的 DRM 客户端累计时间差，不是隐藏的整机 GPU 硬件计数器。
显示刷新率与应用 FPS 分开处理；游戏 FPS 依赖对应的受支持数据源，无数据时保持未知。
电池功率由电压和电流推导，与整机功耗使用不同字段。Panel 的 POWER 卡片把可信 USB 输入
显示为正、电池放电显示为负；不能拿电池充电功率代替整机功耗。具体字段以
`components/control-panel/pocketds-panelctl.cpp` 和 QML 验证函数为准。

## 下屏输入的归属

键盘通过 AT-SPI 跟踪可编辑控件，用共享的 Type-B 解码器读取下屏触点以支持组合输入。
它不会独占触摸屏。触摸板显示期间才通过 EVIOCGRAB 独占下屏，并将触点转换为相对鼠标、
滚动或按钮操作；隐藏、断线和退出时取消自身输入并释放设备。

Linux 的多点触摸槽位是有状态的：新 tracking ID 不保证重新发送未变化的 X/Y。
`touchpad_raw.py` 保留同一流的槽位坐标；启用、打开设备和丢帧恢复时，读取有界的 evdev
缓存快照。快照中已按住的手指不视为新点击。触摸板取得独占前后检查无触点，避免在用户尚未
松手时接管。恢复与整批事件读取使用同一把锁，GUI 回调带代际标识，旧页面的回调不能修改新页面。

InputPlumber 的桌面鼠标/手柄模式与游戏会话由独立的模式助手协调。手柄测试会临时接管输入，
退出后先释放输入再恢复前态；游戏启动器也必须恢复其改变的模式。这里的设备抓取、模式、
虚拟按钮状态和界面可见性是不同状态，不能用一个 `visible` 布尔值代替全部生命周期。
相关回归见 `tests/touchpad-reader-lifecycle.py`、`tests/touchpad-button-ownership.py` 及输入栈测试。

## 显示与电源

| 硬件 | 固定标识 |
|---|---|
| 上屏输出 / 背光 | `DSI-1` / `ae94000.dsi.0` |
| 下屏输出 / 背光 | `DSI-2` / `sy7758-backlight` |
| 下屏触摸传感器 | `/dev/input/by-path/platform-a88000.i2c-event`，Goodix，原始轴范围 768×1024 |
| 下屏横向像素坐标 | 1024×768；窗口逻辑尺寸与缩放从运行时读取 |
| 音频 UCM | `Qualcomm/sm8550/APS` |

独立亮度由 `pocketds-brightness` 保存在用户私有状态文件中，并通过白名单助手写入对应
背光。关屏期间禁止重放非零亮度；下屏驱动的 raw 亮度需要专门的归零与恢复处理。
合盖服务订阅 `PrepareForSleep`，在有界准备期确认显示关闭，再释放睡眠延迟抑制器。
DPMS 请求已提交不等于两块物理屏幕已经关闭。

日用深度睡眠是额外验收和显式启用的路径。准入检查核对机型、内核、存储状态、补丁文件及
实际运行进程的插件映射；磁盘已换成新插件而进程仍运行旧映射，也必须拒绝。PowerDevil 的
Pocket DS 补丁在恢复后发出亮屏请求前检查合盖状态，详见
[`components/powerdevil`](../components/powerdevil/README.md)。正常日用不附带实验用 RTC 救援。

上屏的 `actual_brightness` 在当前驱动中会发起 DSI 读取，并非纯缓存字段；不要把它加入
周期观测器。显示排查应使用已验证的缓存字段与对应流程，避免观测本身改变显示链路。

## 语音、账户与外部运行时

键盘优先调用使用者自行配置的 OpenAI 兼容转写 API；HTTPS 地址、模型及 API Key
存放在独立私有配置中，无默认服务，也不生成或发送设备 ID。失败或未配置时，只有已安装且
通过检查的本地 SenseVoice 或 Whisper
后端才参与回退。仓库不附带个人服务授权或模型。语音会话绑定触发时的输入目标，取消、目标
变化或过时回调不能再粘贴结果。录音根据实际输入源选择蓝牙/USB 的系统路径或内置麦克风路径。

Codex 额度使用本机用户的登录状态，游戏启动器依赖外部程序。没有授权、模型或应用时，相关
可选功能不可用；不能在 UI 中把文件存在或服务 active 当作完整功能验证。外部来源与版本见
[DEPENDENCIES.md](DEPENDENCIES.md) 和 [THIRD-PARTY.md](../THIRD-PARTY.md)。

## 安装与维护边界

主安装器串联输入栈与键盘的窄事务，再更新其他覆盖文件和服务。它会备份已有文件，但不是
完整包管理器或整机快照工具。界面代码、共享 Python 模块、系统助手及策略需要作为兼容的一代
共同部署；只更新磁盘文件不保证运行进程已加载新版本。

开发先用离线测试验证状态机与失败路径，再做匹配环境的构建和必要实机验收。
详细步骤见 [安装、升级与撤回](INSTALL.md)；历史内核实验不属于普通安装流程。
